Implementation

ARCH-005 - completed with bounded reductions. kim_preview entry combines state, exact target selection, dependency validation and the live pre-item guard. The shell consumes its NUL-delimited response only to select the work. A combined location stage command writes and verifies within one parsed-plan lifetime, reusing the selected immutable entry and one integrity digest. It rechecks live source, destination and dependency identities after writing. Canonicalization was moved outside the entry-search generator. Both final publication guards still independently reload and validate the approval plan. The existing write, verify, and preview query interfaces remain available.

ARCH-006 - completed for normal result delivery. Ready, problem and repair counts update from the affected row, including replacement results. Execution job counts also update on completion rather than rescanning on every stage. Diagnostics append for ordered results and rebuild only for replacements or out-of-order problems. Warning groups accumulate once, preserving original source identities and existing captions/details; hidden technical text is materialized on disclosure. Selected properties rebuild only when the selected row, generation or recipe changes. The Run predicate additionally requires ready == len(files), so cancelled rows cannot authorize execution.

Generation rejection, pending-worker gating, recipe/destination invalidation, validated execution snapshots, cancellation and existing diagnostic text remain. Replacing a warning-bearing row genuinely rebuilds warning groups. Expanded warning details must reflect new data and can still regenerate the detailed text; this batch does not introduce a new presentation framework.

ARCH-007 - completed for compatible selective-removal verification. A single ExifTool JSON query verifies the union of known empty GPS/AI removal selections. Family 0/1/4 groups, duplicate instances and structured values are retained. Only absent fields or empty strings satisfy removal; arrays, objects, numeric zero, unexpected nonempty values and malformed/duplicate JSON fail closed. Retained structured location text is not accidentally included in removed leaf selections. The allowlist prevents unrelated queries from entering this path. Scalar/copyright/date comparisons keep their exact existing -s3 print conversion. Without Python on PATH, verification retains the complete original per-tag path. Further scalar/date batching is deferred because it requires careful ExifTool print-conversion equivalence and gives less benefit here.

ARCH-008 - completed for selected planning observations. Copyright, GPS, AI, ICC description and ICC information share one deliberate text-valued query for ordinary inputs. Numeric header/date inspection remains separate, as does the existing descriptive-metadata preservation query. Family 0/1 matching preserves EXIF/IPTC/XMP distinctions. PSD original-document metadata and normalized composite ICC observations remain separate because they describe different objects. Private execution-source snapshots are still inspected freshly. No broad metadata cache or new PSD parser was introduced.

ARCH-009 - completed. Intrinsic logo identity, oriented dimensions, opacity, profile/color checks and decode validation are reused within an explicit batch/generation context, bounded to 64 paths and discarded on exit. Every lookup checks current regular-file identity and the current sRGB policy profile identity. Replacement, metadata changes, symlinks, policy changes and cancellation cannot silently reuse old facts. Placement/scaling stays per image. GUI workers and direct Recipe preview/execution share the scope only within their batch; private execution-logo copying, identity checks, color inspection and rendering remain fresh.

Safety checks deliberately retained

Independent decoded-pixel, binary ICC, JPEG/WebP encoded-data, TIFF encoded-data, ISOBMFF container and PNG presentation checks remain in place. Staging and atomic create/explicit-overwrite publication are unchanged. Both final GPS publication guards reload the plan. Original-source metadata digests, reference/GPX identity, destination identity, hardlink/symlink rejection, exact approved names, external create/prompt policy and cancellation gates remain mandatory.

No persistent service, global approval cache, new dependency, image-processing concurrency, format support, output naming or user workflow was introduced.
